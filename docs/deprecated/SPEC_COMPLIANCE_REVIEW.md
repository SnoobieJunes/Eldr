### Findings

No Critical or High findings. The ratchet core, rekey machinery, envelope, and authenticity gates implement the SPEC/NIP faithfully, and the two chaos-matrix-era fixes (N6 deferred folds, N7 `tgt`+history) are present in code exactly as DEVIATIONS describes.

**[MEDIUM] M-1: `ai_window` crosses the protocol-package boundary unvalidated** — `PQRCMessenger.decryptAndEmit` copies `rumor.aiWindow` straight into `ReceivedMessage` (Packages/PQRCNostr/Sources/PQRCNostr/PQRCMessenger.swift:362) without calling `AIWindowAnnouncement.hasValidSignature()` or checking `enabledBy` against the sender's binding-verified identity key. SPEC §13.3 makes the announcement "valid only when signed by the human identity key". The enforcement does exist — `AgentEngine.receiveWindow` checks `enabledBy == sender`, the Ed25519 signature, and the ≤2 h bound, and `authorizeAutonomousSend` fails closed (Packages/PQRCAgent/Sources/PQRCAgent/AgentEngine.swift:70–83, :134–148) — but it lives in PQRCAgent, one layer above this review's packages. Any consumer that renders the "AI active" indicator from `ReceivedMessage.aiWindow` without routing through the engine would display a forgeable indicator (e.g., a window self-signed by an agent key with `enabledBy` set to that same agent key passes `hasValidSignature`, which is self-referential by design). Impact: defense-in-depth gap, not an exploitable hole in the shipped wiring; severity Medium because SPEC §13's MUSTs deserve enforcement at, or below, the layer that surfaces the value. Part II confirms the app's indicator path goes through `AgentEngine.receiveWindow`.

**[LOW] L-1: `NSLock` + `@unchecked Sendable` in Sources** — `SeededRandomSource` and `FixedClock` (Packages/PQRCCore/Sources/PQRCCore/Support/Seams.swift:60–122) use `NSLock` and `@unchecked Sendable`. Both carry the written justification CLAUDE.md requires, and neither holds session/ratchet state, so the convention's intent is met — but they are compiled into the production library (and `LocalRelaySimulator` uses `SeededRandomSource` for chaos), so "No locks" is violated in letter. Moving them to a test-support target (or converting to actors/`Mutex`) would close the gap.

**[LOW] L-2: One force unwrap** — NostrKeypair.swift:43: `Data(key!.xonly.bytes)` after a rejection-sampling loop that exits only when `key != nil`. Provably non-nil, but CLAUDE.md's "no force unwraps" admits no carve-out short of "truly unreachable", and a `guard let`/`while let` restructure costs nothing.

**[LOW] L-3: Chunking fallback (SPEC §11.2) not implemented** — the >64 KB path is pointer-only (`BlobCipher`, Packages/PQRCNostr/Sources/PQRCNostr/LocalBlossomSimulator.swift:57–101); there is no chunk-split/reassemble code in either package. The hard invariant itself holds — `Padding.bucket(for:)` throws `plaintextExceedsInlineLimit` above 65536 (Padding.swift:14–20) and `PQRCSession.encrypt` cannot inline oversized bodies (SessionTests.swift:171–179) — and DEVIATIONS T5 records the gap accurately. It only bites once a real relay's `max_content_length` constrains the pointer envelope, which the in-process relay never does.

**[LOW] L-4: Rumor `pqrc_version` not checked on receive** — `RumorContent.version` is decoded but never compared to `"1"` in the receive path (PQRCMessenger.swift:285–304, PQRCSession.swift:139–152). Cross-version traffic still fails closed because the receiver bakes the constant `"1"` into the AD (PQRCSession.swift:10) so AEAD rejects it — but it surfaces as a generic `decryptionFailed` that lands in the retry queue and eventually quarantines as "retry queue overflow", instead of a clean, immediate version rejection. Cheap fix: guard `rumor.version == PQRCConstants.version` before decrypting.

**[LOW] L-5: Deterministic one-time-prekey selection can wedge concurrent initiators** — `PQXDH.initiate` always takes `bundle.otp.first` / `bundle.otpPQ.first` (PQXDH.swift:74, :87), and `PrekeyManager.publicBundle` sorts the published lists deterministically (PrekeyManager.swift:62–63). Two initiators working from the same bundle snapshot therefore pick the *same* OTP; the responder rejects the second with `oneTimePrekeyAlreadyConsumed` (PrekeyManager.swift:89–95) and quarantines the handshake (PQRCMessenger.swift:330–333) with no NACK back to the initiator. Confidentiality is unaffected (fail-closed), but the losing session silently stalls. Random selection plus an initiator-side retry on a re-fetched bundle would fix the liveness. SPEC §4.1 only specifies the exhaustion race, so this is a quality gap, not a violation.

**[LOW] L-6: `PQXDH.initiate` is not type-gated on verified input** — the binding/bundle verification chain is enforced by type state up to `VerifiedContact` (fileprivate `VerifiedBinding.init`, IdentityBinding.swift:78–82) and every in-repo caller verifies first (`establishSession` re-runs `verifySignatures`, PQRCMessenger.swift:162; `fetchVerifiedPeer` is all-or-nothing, :117–142). But `PQXDH.initiate` itself accepts a plain `PrekeyBundle` and relies on a doc-comment contract (PQXDH.swift:54–57). A `VerifiedPrekeyBundle` wrapper would extend invariant 7's only-way-to-obtain-keys pattern to the handshake API.

**[INFO] I-1: SPEC §8.2's illustrative field names superseded by the NIP** — the implementation uses `dh`/`pn`/`n`/`pq` and `ptr` (Rumor.swift:181–192, RatchetHeader.swift) where SPEC §8.2 sketches `dh_pubkey`/`prev_chain_len`/`message_number`/`pq_rekey`/`content_pointer`, and `enabled_by` is base64 (Data's Codable default) where SPEC §13.3 shows hex. This follows the declared hierarchy (NIP is wire law; CLAUDE.md names the short fields explicitly) and N1/N9 record the lineage. Likewise AD binds `participant_type` rather than SPEC §8.3's prose `sender_role` — N9 documents the choice, the two fields are 1:1-coupled by the A8 gate, and CLAUDE.md invariant 5 itself names `participant_type`. No action needed beyond keeping the SPEC text in sync upstream.

**[INFO] I-2: Unknown fields are ignored, not preserved** — re-encoding a `RumorContent` drops unknown keys (explicit `CodingKeys`). CLAUDE.md permits "preserved-**or**-ignored", and nothing in the protocol packages re-publishes foreign rumors, so this is compliant; worth remembering if a relay/forwarding role is ever added.

**[INFO] I-3: Retry-queue behavior under hostile input** — undecryptable envelopes from a verified contact are re-presented after every successful decrypt with no per-envelope attempt cap, bounded at 256 oldest-first (PQRCMessenger.swift:408–419). This matches N16 verbatim (including the rationale for capless retries). Worst case is O(256) extra decrypt attempts per inbound message from a peer deliberately sending garbage — bounded, by design, acceptable. Similarly `processedWrapIDs` grows without bound (PQRCMessenger.swift:277–281); fine for v1 lifetimes, worth an LRU eventually. (The companion security audit rates this Medium with an amplification angle — see EXTERNAL_CROSSCHECK_REVIEW.md.)

**[INFO] I-4: `Task.sleep` exists, but only in transport pacing** — PQRCMessenger.swift:236 (publish backoff) and LocalRelaySimulator.swift:208 (chaos latency injection). Neither is key-schedule code; `DoubleRatchet` cannot even reach a clock (no member, confirmed by the Mirror-based test RatchetTests.swift:460–463 plus the divergent-clock behavioral proof :468–501). Invariant 1 is satisfied as written.

**[INFO] I-5: Timestamp fuzz uses 64-bit modulo** — `value % (window+1)` (PQRCSession.swift:29) has modulo bias ≈ 2⁻⁴⁶ over a ~2¹⁷·⁴ window: cryptographically irrelevant for a traffic-analysis fuzz, and not a "custom primitive". Noted for completeness.

**[INFO] I-6: DEVIATIONS.md accuracy** — every protocol-relevant entry was checked against code and matches: N2 (bidirectional binding — IdentityBinding.swift/PQRCEvents.swift), N3 (`ik_dh` — PrekeyBundle.swift:10–13), N4 (rekey-target invariant — PQXDH.swift:122–127), N5 (optional `lrp`, omissible dh3 — PQXDH.swift:71–82), N6 (deferred folds — DoubleRatchet.swift:188–229; pq_rekey.json regenerated pre-freeze as the history states, vector asserts root unchanged at the rekey and fold landing at the next DH boundary, RatchetTests.swift:298–323), N7 (`tgt` + `maxKEMHistory = 8` — DoubleRatchet.swift:38, :254–271), N8 (both-direction counting), N9 (`agent_sig` + AD binding), N10 (`pqrc-seal-v1`, x-coordinate-only ECDH — SealCipher.swift:22–28), N11 (bundle as JSON content), N12 (kind 1420; rumor pubkey == seal pubkey — GiftWrap.swift:90–91), N13 (derived ratchet nonces, injected `NonceSource` elsewhere — DoubleRatchet.swift:355–366 vs SealCipher/BlobCipher/EncryptedStore), N14 (prefix outside bucket; 65536→65556 confirmed in padding.json), N15 (one fuzzed timestamp, test-enforced), N16 (256-entry capless retry queue). **No misdescriptions found.** Tech-debt entries T2 (prekey state not persisted), T5 (no chunking), T8 (`ik_dh` not in the 10420 assertion) accurately describe real gaps in these packages.

### Gaps & recommendations

Prioritized; none block conformance of the shipped v1.

1. **(M-1)** Validate `ai_window` at the messenger: in `decryptAndEmit`, drop-or-flag announcements whose `enabledBy` ≠ the contact's binding-verified identity key or whose signature fails, before yielding `ReceivedMessage`. ~10 lines; makes SPEC §13.3 enforceable below every UI. Until then, the app's indicator path must use `AgentEngine.receiveWindow` exclusively (Part II row 19 confirms it currently does).
2. **(L-4)** Add an explicit `rumor.version == "1"` guard in the receive path (`PQRCSession.decrypt` or `processUnwrapped`) so future-version traffic is rejected legibly instead of cycling the retry queue.
3. **(L-5)** Randomize OTP selection in `PQXDH.initiate` and surface handshake-consume failures to a re-initiation path; queue behind T2 (prekey persistence), which is the bigger prerequisite for any real transport.
4. **(L-6)** Introduce a `VerifiedPrekeyBundle` type-state so `PQXDH.initiate` cannot be handed unverified keys — completes the invariant-7 pattern already used for bindings.
5. **(L-1, L-2)** Mechanical cleanups: move `SeededRandomSource`/`FixedClock` out of the production target (or convert to `Mutex`/actor), and restructure the rejection-sampling loop in `NostrKeypair.init(randomSource:)` to remove the lone force unwrap.
6. **(L-3 / T5)** Implement chunking (SPEC §11.2) before swapping in a real relay transport whose `max_content_length` can bite; the conformance suite (ConformanceSuite.swift:14–101) is already positioned as the acceptance gate for that swap.
7. **Upstream doc sync (I-1)**: fold the NIP's short field names, the base64 `enabled_by`, and the `participant_type`-in-AD choice back into SPEC §8.2/§8.3/§13.3 prose at the next SPEC revision, so the SPEC > NIP precedence rule can't be misread against the implementation.

### Findings

**[HIGH] H1 — CI retry policy can mask flaky security failures; the "no-retry for `.security`" rule is claimed but not implemented.** TEST-PLAN §12 requires "Fail the build on any `.security`-tagged failure regardless of retry policy." `.github/workflows/ci.yml:39–46` comments "Security-tagged failures fail the build, no retries" but then passes `-retry-tests-on-failure -test-iterations 2` to the *entire* app test run — a security test that fails once and passes on retry will green the build. Compounding it, the app-target suite isn't actually tagged: `App/PQRCTests/SecuritySuiteTests.swift:15` declares `@Suite("Security & privacy regression (TEST-PLAN §9)", .serialized)` with no `.tags(.security)` (its own doc comment at line 13 claims the tag), so no tooling could even single it out. The package-side `.security` tag exists (PaddingEnvelopeTests.swift:204) and the `swift test` jobs have no retries, so package security tests are safe; the gap is the xcodebuild job only.

**[HIGH] H2 — THREAT_MODEL.md exists in three tracked locations with two divergent contents; the TestVectors copy is staged garbage.** Root `THREAT_MODEL.md` (15,948 B, "PQRC Threat Model v1", assets/adversaries format) and `docs/THREAT_MODEL.md` (7,695 B, "Generated per SPEC §15.3", protections/limits format) are entirely different documents; both were added in commit c3b5208. `TestVectors/THREAT_MODEL.md` is a byte-identical copy of the root file (verified by `diff`), currently *staged but uncommitted* (`git status: A TestVectors/THREAT_MODEL.md`) — almost certainly an accidental copy; it does not belong among frozen vectors (the vector loaders only read `*.json`, so no test impact, but it pollutes the freeze directory and would be committed on the next `git commit`). Canonical per CLAUDE.md repo layout ("docs/ — … generated THREAT_MODEL.md") and SPEC §15.3 is **docs/THREAT_MODEL.md**, which fully satisfies the DoD honesty items. Recommended: unstage/delete `TestVectors/THREAT_MODEL.md`; either delete the root copy or mark it as the protocol-author draft and cross-link, so the two cannot silently diverge further.

**[MEDIUM] M1 — Anthropic/remote AI provider is unreachable from the app; the Settings AI section is partly cosmetic.** `AnthropicAPIProvider` itself is sound (key injected, never hardcoded; minimal 20-entry context; plausible model id `claude-haiku-4-5-20251001`; AnthropicAPIProvider.swift:10–62). But: the provider picker writes `@AppStorage("aiProvider")` that nothing reads (SettingsView.swift:11,46–55); the consent alert's "Enable remote AI" button is an empty closure (SettingsView.swift:105); there is no API-key entry UI and no Keychain item for it despite APP-SPEC §3 listing "optional Anthropic API key" as a Keychain item; `bootSingle` always selects FoundationModels-or-Mock (PQRCApp.swift:82–84) and `PersonaRuntime.setProvider` (PersonaRuntime.swift:76) has no caller. Consent *copy* matches APP-SPEC §9 verbatim. D3's "off by default" is trivially true — it can never turn on. Not recorded in DEVIATIONS.

**[MEDIUM] M2 — CI destination has no simulator OS pin despite the project's own recorded requirement.** DEVIATIONS T6 (docs/DEVIATIONS.md:145–148) says to pin `OS=26.5` "on machines that also have beta runtimes installed — an ambiguous name can silently resolve to a beta." Both xcodebuild invocations in ci.yml use `'platform=iOS Simulator,name=iPhone 17 Pro'` with no OS (ci.yml:44,75). GitHub macOS images routinely carry multiple iOS runtimes (incl. betas), so the documented failure mode applies to CI exactly.

**[MEDIUM] M3 — Several APP-SPEC UI requirements are absent and unrecorded in DEVIATIONS.** (a) §6.1 list affordances: no unread badge, no swipe pin/delete, no relative time, no pull-to-refresh (grep for `refreshable|swipeActions|badge(` across App/PQRC is empty; MainView.swift:26–38); §2's "RelaySync drains on scenePhase change and pull-to-refresh" has no `scenePhase` handling (moot with the always-streaming in-process relay, but unrecorded). (b) §6.1/D12 message-request *acceptance*: requests render as inert `Label`s (MainView.swift:18–23) with no accept flow — the gate works (UI-tested, PQRCUITests.swift:184) but a requested conversation can never become a real one. (c) §6.4/D13 "Mark as verified" is a local `@State` toggle (ConversationDetailsView.swift:12,27) never persisted to `ContactModel.verified` and never reflected into `ConversationVM.verified`, so the shield badge (MainView.swift:97–101) can never appear. (d) §6.3 PhotosPicker attachments: absent from the composer (ConversationView.swift:161–213).

**[MEDIUM] M4 — Two of the seven performance budgets are not metric-wired.** TEST-PLAN §11 requires XCTest `measure` + XCTMetric with baseline-relative regression. The 1 MB blob path and 500-envelope drain use manual `Date()` deltas and `print("PERF SOFT WARNING…")` that can never fail or baseline (PerformancePipelineTests.swift:73–84,131–151). DEMO.md:90–91 honestly records the drain at 4.4 s against the 3 s budget on simulator — under the current wiring that overage would never trip CI even after baselines exist. Launch, scroll-hitch, memory, 1 KB and 64 KB paths are properly metric-based.

**[MEDIUM] M5 — Outbox/status plumbing is vestigial at the app layer.** APP-SPEC §3 lists `OutboxEnvelope` and `PrekeyState` SwiftData models; neither exists (SwiftDataStore.swift:13–111 — six models). `PrekeyState` absence is recorded (T2); `OutboxEnvelope` absence is not. `MessageStore.updateStatus` has zero callers (grep), and `PersonaRuntime.sendMessage` saves outgoing messages directly as `"sent"` (PersonaRuntime.swift:253), so the `"queued"` UI state (MessageBubble.swift:37) is dead — retry/queueing exists only in-memory inside `PQRCMessenger`, and queued sends do not survive an app kill.

**[MEDIUM] M6 — `completeFileProtection` is claimed in three places but set nowhere.** APP-SPEC §3 ("The SwiftData container additionally uses `completeFileProtection`"), SwiftDataStore.swift:133 ("the container additionally uses complete file protection"), and docs/THREAT_MODEL.md:21 ("…complete file protection | `atRest_noPlaintextInStoreFiles`") all assert it; grep for `fileProtection|completeFileProtection|NSFileProtection` across App/Packages/pbxproj/entitlements returns nothing, and `makeContainer` (SwiftDataStore.swift:236–250) sets no protection attribute — leaving the iOS default (CompleteUntilFirstUserAuthentication). Impact is contained because every sensitive field is envelope-encrypted under the SE-wrapped master key (the canary test proves no plaintext at rest), but the threat model overstates a defense-in-depth layer, which violates its own honesty rule.

**[LOW] L1 — 16–64 KB pastes get the "sends as encrypted attachment" chip but go inline, not via the blob path.** APP-SPEC §6.3 says >16 KB "routes through the blob path"; the composer chips at >16,384 B (ConversationView.swift:190) while `PersonaRuntime.sendMessage` only takes the pointer path above 65,536 B (PersonaRuntime.swift:235). The SPEC-§11 MUST (>64 KB never inlined) is enforced and tested (SessionTests.swift:171; PaddingEnvelopeTests.swift:59), and inlining 16–64 KB is privacy-equivalent (still bucket-padded), but chip copy is misleading for that range and the APP-SPEC deviation is unrecorded.

**[LOW] L2 — `SystemRow` is dead code; ai_window start/expiry and roster changes don't render as system rows.** APP-SPEC §6.2 calls for system rows; `SystemRow` (MessageBubble.swift:100–110) has zero usages (grep). Window starts arrive as ordinary human bubbles ("enabled always-on AI", PersonaRuntime.swift:330–331), roster changes as "updated the group" messages (PersonaRuntime.swift:297–302); expiry produces no row at all (the banner just clears).

**[LOW] L3 — TEST-PLAN §7's `replay_oldEnvelopeRejected` has no named implementation.** Behavior is covered compositely — relay dedupe (TransportTests.swift:92), chaos duplicate-injection asserting exactly-once (ChaosMatrixTests.swift:92–93), and ratchet-level replay rejection (RatchetTests.swift:189–193, 449–453) — but a reviewer mapping plan→tests by name will miss it; a messenger-level "old envelope re-presented after processing is dropped via ProcessedEventID" test would close it.

**[LOW] L4 — UI test drops the expiry half of `aiWindow_bannerAppearsForPeer_andExpires`.** PQRCUITests.swift:131–141 asserts appearance only, with a comment delegating expiry to the engine suite (which does fail-close, AgentIntegrityTests.swift:127). The SPEC §13.3 *indicator-clearing* behavior on a peer's screen is implemented (banner predicate `until > now`, AppModel.swift:196–202) but untested at the UI layer.

**[LOW] L5 — Minor convention breaches.** One force unwrap: `URL(string: "https://api.anthropic.com/v1/messages")!` (AnthropicAPIProvider.swift:41) — constant and safe, but CLAUDE.md says no force unwraps without exception. Settings: "Republish bundle" button only refreshes the displayed count, it republishes nothing (SettingsView.swift:39–43); relay add/remove and Debug chaos sliders (APP-SPEC §10) absent; delete-conversation UI absent (`deleteConversation` store API exists, SwiftDataStore.swift:200, no caller); default-invite-duration setting absent.

**[LOW] L6 — Determinism mandate honored in spirit, not to the letter.** TEST-PLAN §1: "No unit test touches the network, the real clock, or system randomness." No network/`Date()`/`DispatchQueue` in package tests (grep clean) and all protocol time runs on `FixedClock`; however async-delivery polling uses real `Task.sleep` (TestSupport.swift:107,150; AgentWireTests.swift:47 — bounded waits, can only cause slowness, not flaky assertions), and a few live round-trip tests use `SystemRandomSource()`/`SystemNonceSource()` where assertions are property-based rather than byte-based (EnvelopeTests.swift:78,154–170; PQXDHTests.swift:162; TransportTests.swift:18).

**[INFO] I1 — Vector freeze relies on git discipline, as designed.** `loadOrGenerate` regenerates a *deleted* vector silently (VectorSupport.swift:43–51); the committed bytes are the contract, and the policy (delete → regenerate → record in DEVIATIONS, done once for pq_rekey per N6) is documented. Byte-exactness is directly asserted for giftwrap (re-wrap equality, EnvelopeTests.swift:61) and field-exactly for ratchet/rekey replays; binding/pqxdh/padding vectors are verified semantically.

**[INFO] I2 — UserDefaults holds only non-secret values.** `displayName`, `aiProvider`, `ephemeralReceivingKeys` (PQRCApp.swift:86; SettingsView.swift:11–12; OnboardingView.swift:57) — no key material or message content; CA92.1 declared in PrivacyInfo.xcprivacy. The user's own display name is plaintext-local while contact nicknames are encrypted (D11/A2); acceptable but worth a one-line DEVIATIONS note.

**[INFO] I3 — Strengths worth keeping.** A1 (no payload logging at all, enforced by an OSLogStore canary with a positive control that entries were captured) is stronger than invariant 12 requires. The agent-integrity suite tests the *hostile* path (forged label over real ratchet state through the real relay, AgentWireTests.swift:172). `AgentEngine` re-checks authorization per message mid-turn (AgentEngine.swift:177–181), so expiry/withdrawal mid-turn stops output. The accessibility audit's exclusions are narrow and documented with rationale (A7; PQRCUITests.swift:203–218).

### Gaps & recommendations

1. **Fix CI security-retry semantics (H1):** tag `SecuritySuiteTests` `.security`, split the app job into a no-retry run of PQRCTests (or at least the security suite via `-only-testing`) and a retried UI run; keep the comment honest.
2. **Resolve the threat-model trio (H2):** `git restore --staged TestVectors/THREAT_MODEL.md` and delete the file; declare docs/THREAT_MODEL.md canonical; delete or clearly re-title the root draft.
3. **Pin the CI simulator OS (M2):** `name=iPhone 17 Pro,OS=26.5` in both xcodebuild destinations, per the project's own T6.
4. **Wire the AI provider setting or record it (M1):** read `aiProvider` at boot/`setProvider`, add Keychain-backed key entry behind the consent alert, or add a DEVIATIONS `[tech-debt]` entry stating remote inference is scaffolded-only in v1.
5. **True up at-rest claims (M6):** either set `FileProtectionType.complete` on the store directory (or container options) or soften APP-SPEC/THREAT_MODEL/source comments to "envelope encryption + default iOS file protection."
6. **Convert blob/drain perf tests to `measure` with XCTMetric (M4)** so the baseline mechanism actually covers them; the 4.4 s drain number already on record makes this the first budget likely to regress unnoticed.
7. **Close the small UI deltas or record them (M3, L1, L2):** message-request accept action, persisted verified flag, pull-to-refresh/swipe/badge/timestamps, PhotosPicker, system rows, 16–64 KB chip copy — each is either an afternoon fix or a one-line `[app-only]`/`[tech-debt]` DEVIATIONS entry; today they are silent deviations, which CLAUDE.md forbids.
8. **Add the missing named tests (L3, L4):** messenger-level `replay_oldEnvelopeRejected` (ProcessedEventID path) and a UI assertion that the peer's banner disappears after expiry (drive `now` past `active_until` with a short synthetic window).

**Bottom line:** the test suite is genuinely strong — every TEST-PLAN section maps to real, passing, adversarially-minded tests (68 package tests verified green here, including the full 16-combo chaos matrix), the frozen-vector regime works, the agent-integrity and privacy invariants (8–12) are enforced in code *and* tests, and DEMO/THREAT_MODEL/DEVIATIONS meet the Definition of Done. The defects are concentrated at the edges: CI policy fidelity, documentation duplication, an unwired Settings surface, and a handful of unrecorded APP-SPEC UI deviations.
